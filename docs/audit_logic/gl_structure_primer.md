# SAP GL 구조 입문 — 비SAP 독자용

이 문서는 SAP ERP와 GL 데이터 구조를 모르는 독자(CS 백그라운드, 데이터 엔지니어 등)를 위한 입문 설명이다.  
이 파이프라인이 왜 7개 테이블을 병합하고, 왜 계정 계층이 필요한지를 이해하는 데 목적이 있다.

---

## 회계 감사에서 GL이란

**GL(General Ledger, 총계정원장)**은 회사의 모든 회계 거래가 기록되는 핵심 장부다. 모든 입출금, 비용, 수익이 계정(Account)별로 기록된다.

감사인은 GL을 검토해 재무제표의 정확성을 검증한다. 특히:

- 어떤 계정에 얼마가 기록됐는가
- 언제, 누가, 어떤 전표로 기록했는가
- 비정상적인 패턴이 있는가

---

## SAP에서 GL 데이터가 분리된 이유

SAP ERP는 데이터를 목적별로 분리된 테이블에 저장한다. 감사인이 필요한 정보는 여러 테이블에 흩어져 있다.

### 주요 테이블 구조

| 테이블 | 약어 의미 | 포함 내용 |
|---|---|---|
| BKPF | Buchhaltung Kopf (전표 헤더) | 전표번호, 전기일, 전표유형, 역분개 여부 |
| BSEG | Buchhaltung Segment (전표 라인) | 계정코드, 금액, 거래처, 코스트센터 |
| SKA1 | Sachkonto (계정 마스터 코드) | 계정코드 |
| SKAT | Sachkonto Text (계정 마스터 명칭) | 계정명 |
| KNA1 | Kunden (고객 마스터) | 고객 코드, 고객명 |
| LFA1 | Lieferanten (공급업체 마스터) | 공급업체 코드, 공급업체명 |
| CSKT | Cost Center Text (코스트센터) | 코스트센터 코드, 명칭 |

### 왜 BKPF와 BSEG가 분리되어 있는가

회계에서 하나의 거래(전표)는 반드시 차변(Debit)과 대변(Credit)으로 분개된다.

**예: 100만원 비용 지급**
```
차변: 비용 계정(판매관리비)  100만원
대변: 현금 계정(보통예금)    100만원
```

이 전표는 BKPF에 헤더 1건, BSEG에 라인 2건으로 저장된다. 하나의 전표가 여러 라인을 가지므로 헤더와 라인을 별도 테이블로 분리하는 것이 데이터베이스 정규화 원칙에 맞다.

이 파이프라인은 BKPF와 BSEG를 `doc_no`(전표번호)로 Join하여 하나의 GL 레코드로 만든다.

---

## 전표(Voucher)란

전표는 회계 거래의 기본 단위다. 하나의 전표에는 반드시 차변 합계 = 대변 합계인 복수의 라인이 포함된다.

**전표 구조 예시:**

| doc_no | line_no | 계정 | 차변(D) | 대변(C) |
|---|---|---|---|---|
| 1001 | 1 | 판매관리비 | 1,000,000 | |
| 1001 | 2 | 보통예금 | | 1,000,000 |

이 구조가 이 파이프라인의 **전표 드릴다운 UI**의 기반이다.  
원장에서 특정 거래를 클릭하면 해당 `doc_no`의 모든 라인(차변·대변 모두)을 보여준다.

## SAP 금액 수출 형식 3가지

SAP는 GL 데이터를 수출할 때 설정에 따라 세 가지 다른 금액 형식을 사용한다.

**A형 (절대금액형 / 차대분리):**
```
debit_amount | credit_amount
   100,000   |       0
       0     |   100,000
```

**B형 (순금액형 / 부호):**
```
amount
+100,000
-100,000
```

**C형 (차대분리형 / A형 변형):**  
컬럼명이 A형과 다른 경우. 내용은 동일.

이 파이프라인은 `config_clean.yaml`의 `gl_format` 설정으로 세 가지 모두 처리할 수 있다.  
클라이언트마다 다른 수출 설정이 이 처리의 필요성을 만든다.

## 계정 계층(Account Hierarchy)이란

재무제표는 계정 계층 구조로 작성된다.

```
대분류: 자산 (Asset)
  중분류: 유동자산 (Current Asset)
    세분류: 현금 및 현금성자산
    세분류: 매출채권
    세분류: 재고자산
  중분류: 비유동자산 (Non-current Asset)
    ...
```

SAP에서 이 계층은 **계정과목표(Chart of Accounts)**로 관리된다. 그러나 감사 현장에서 CoA가 최신 상태로 제공되지 않거나, 아예 제공되지 않는 경우도 있다.

이 파이프라인은 **계정코드 Prefix**를 이용해 계층을 자동 생성한다.

**SAP 표준 계정코드 Prefix 구조 예시:**
```
1xxxxx → 자산
  11xxxx → 유동자산
    110000 ~ 119999 → 현금 및 현금성자산
  12xxxx → 비유동자산
2xxxxx → 부채
3xxxxx → 자본
4xxxxx → 수익
5xxxxx → 원가
6xxxxx → 판매관리비
```

이 구조를 이용하면 CoA 없이도 계정코드만으로 대/중분류를 추론할 수 있다.

## 전표유형(Document Type)이란

SAP에서 전표유형은 거래의 성격을 분류하는 2자리 코드다.

| 전표유형 | 의미 |
|---|---|
| SA | 수동 전기 (General Ledger Manual Entry) |
| KR | 구매 송장 (Vendor Invoice) |
| DR | 매출 전표 (Customer Invoice) |
| ZP | 지급 전표 (Payment) |
| AB | 기타 계정 이체 |

`large_manual_entry` Rule이 `doc_types: [SA]`를 검사하는 이유는, SA(수동 전기)가 자동화 프로세스 없이 사람이 직접 입력한 전표이기 때문이다. 고액 수동 전기는 내부통제 관점에서 승인 여부를 확인해야 하는 핵심 검토 대상이다.

## 감사 조서(Working Paper)란

감사 조서는 감사인이 감사 업무를 수행한 근거를 기록하는 문서다. 이 파이프라인의 **Excel 조서 출력**은 다음 구조로 생성된다:

**Sheet 1 — 원장(Ledger):**  
특정 계정의 기간 내 모든 거래 내역. AutoFilter로 전표유형, 금액 범위 등 필터 가능. 이상거래로 탐지된 항목은 배경색으로 하이라이팅.

**Sheet 2 — 월별 집계:**  
계정별 월간 차변/대변/순액 집계. 전기 추세 이상 탐지에 활용.

**Sheet 3 — 전표유형별 집계:**  
전표유형 × 이상탐지 Flag 교차 집계. 어떤 전표유형에서 이상이 집중되는지 파악.

이 조서는 감사인이 "어떤 계정을 어떤 기준으로 검토했는가"를 기록하는 감사 근거 문서로 활용된다.
