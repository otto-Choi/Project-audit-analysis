# Rule Engine 설계 근거

이 문서는 8개 Rule이 "왜 선정되었는가"를 감사 리스크 관점에서 기록한다.  
Rule 파라미터 설정 참조: [`config_reference.md`](config_reference.md)

---

## Rule 선정 원칙

Rule은 다음 기준으로 선정했다:

1. **감사 조서에 근거로 쓸 수 있는가** — 탐지 조건이 감사인이 설명할 수 있는 수준이어야 한다
2. **SAP GL 데이터에서 직접 판단 가능한가** — 외부 데이터 없이 GL 필드만으로 탐지 가능해야 한다
3. **클라이언트별 threshold가 달라야 하는가** — config 파라미터화의 실제 필요성이 있어야 한다

---

## Rule 상세

### Rule 1 — Weekend Posting (비업무일 전기)

**타겟 감사 리스크:**  
정규 업무 프로세스 외부에서 처리된 전표. 내부통제가 작동하지 않는 시간대의 전기는 승인 없이 처리됐을 가능성이 있다.

**감사 관점:**  
주말·공휴일 전기는 그 자체로 오류나 부정을 의미하지 않는다. 그러나 다른 리스크 지표(고액, 비정상 계정 등)와 결합 시 우선 검토 대상이 된다. ISA 240(부정 위험)에서 통제 취약 시점의 거래를 검토하도록 요구한다.

**탐지 기준:** `weekday` in {5, 6} (토요일, 일요일)

**가중치:** 1 (단독으로는 낮음. 복합 탐지 시 점수 누적)

**현장 적용 시 주의:**  
일부 클라이언트는 월마감을 위해 주말 전기가 정상적으로 발생한다. 이 경우 `enabled: false`로 비활성화하거나, 특정 전표유형을 제외하는 조건 추가가 필요하다.

---

### Rule 2 — Month-end Concentration (월말 집중 전기)

**타겟 감사 리스크:**  
기간 귀속(Period-end Accrual) 조작. 월말에 집중된 전기는 목표 이익 달성을 위한 수익/비용 인식 시점 조작의 패턴으로 나타날 수 있다.

**감사 관점:**  
월말 대규모 수동 분개는 감사에서 핵심 검토 대상이다. ISA 240에서 비정상적 월말 분개(unusual journal entries)를 부정 위험 지표로 명시한다.

**탐지 기준:** 전기일이 해당 월의 마지막 `last_days`일 이내

**파라미터:** `last_days: 3` (기본값. 클라이언트 마감 일정에 따라 조정)

**가중치:** 2

---

### Rule 3 — Reversal Entry (역분개 전표)

**타겟 감사 리스크:**  
전기 취소·원상복구 패턴. 역분개 자체는 정상적인 회계 처리(예: 월간 발생주의 전표의 익월 취소)이지만, 비정상적인 계정 또는 시점의 역분개는 조작의 흔적일 수 있다.

**감사 관점:**  
역분개 전표를 추적하면 원거래와 취소거래 간의 금액 차이, 계정 불일치, 비정상적인 역분개 타이밍을 포착할 수 있다.

**탐지 기준:** `reversal_flag = True` (SAP BKPF 필드에서 직접 추출)

**가중치:** 2

---

### Rule 4 — Duplicate Journal (중복 전표)

**타겟 감사 리스크:**  
동일 거래의 이중 기장. 특히 비용·지급 거래에서 중복 처리 시 손실이 발생한다.

**탐지 기준:** `(doc_no, line_no)` 조합 중복

**가중치:** 3 (발견 시 파급력이 크므로 높은 가중치)

**알려진 문제:**  
현재 key 설계가 `(doc_no, line_no)` 조합으로 되어 있어 샘플 데이터에서 97% 탐지율이 나타났다. 이는 SAP에서 동일 전표번호에 여러 라인이 있을 때 모두 "중복"으로 판정되는 오작동이다. 실무 중복 전표는 다른 전표번호로 동일 내용이 두 번 처리된 경우이므로, `(amount, acc_code, post_date, vendor_no)` 조합 등으로 key를 재설계해야 한다.

→ 상세 재설계 방향: [`../validation/known_issues.md`](../validation/known_issues.md)

### Rule 5 — Unusual Round Amount (비정상 정액 거래)

**타겟 감사 리스크:**  
가공 거래(fictitious transaction)의 특징적 패턴. 실제 거래는 단수가 발생하는 반면, 가공으로 만들어진 거래는 100만 원, 1,000만 원 등 정확한 단위로 처리되는 경우가 많다.

**감사 관점:**  
Benford's Law 분석과 함께 쓰이는 고전적 분석 기법. 특히 비용 처리 계정에서 유효하다.

**탐지 기준:** `abs(amount) % modulus == 0` (기본 modulus: 1,000,000원)

**파라미터:** `modulus: 1000000` (클라이언트 통화 단위에 따라 조정)

**가중치:** 1 (단독으로 유의하지 않음. 복합 탐지 시 점수 누적)

---

### Rule 6 — Large Manual Entry (고액 수동 전기)

**타겟 감사 리스크:**  
승인 한도를 초과한 수동 전기. 특히 SA(수동 전기) 전표유형에서 고액이 발생하는 경우 자동화된 프로세스가 아닌 인적 개입이 있었음을 의미한다.

**감사 관점:**  
내부통제에서 금액별 승인 권한(Authorization Level)을 설정하는 경우가 많다. Threshold를 초과하는 수동 전기는 그 승인 증빙을 확인해야 한다.

**탐지 기준:** `doc_type in doc_types AND abs(amount) > threshold`

**파라미터:**  
- `doc_types: [SA]` — 검사할 전표유형 (클라이언트별로 수동 전기 유형이 다름)
- `threshold: 100000000` — 1억 원 (클라이언트 내부통제 기준에 맞춰 조정)

**가중치:** 3

---

### Rule 7 — Debit-Credit Imbalance (차대불균형 전표)

**타겟 감사 리스크:**  
전표 무결성 오류. 복식부기 원칙상 전표 내 차변 합계와 대변 합계는 일치해야 한다. 불일치는 데이터 추출 오류, 전표 손상, 또는 수동 조작의 흔적일 수 있다.

**감사 관점:**  
데이터 품질 검증과 부정 탐지 모두에 적용된다. 특히 GL 데이터 추출 시 테이블 조인 과정에서 발생할 수 있는 데이터 손실을 감지하는 데 유효하다.

**탐지 기준:** `|sum(debit) - sum(credit)| > tolerance` (전표 단위 집계)

**파라미터:** `tolerance: 0.01` (원 단위 반올림 허용 오차)

**가중치:** 5 (무결성 오류이므로 최고 가중치)

**알려진 문제:**  
순금액형(B형) 전표는 차변/대변을 분리하지 않고 +/- 부호로만 표시하므로, `debit`/`credit` 분리 계산 시 오탐이 발생할 수 있다. 전표유형 필터로 순금액형 전표를 제외하는 처리가 필요하다.

→ [`../validation/known_issues.md`](../validation/known_issues.md) 참조

### Rule 8 — Account-level Outlier (계정별 이상금액)

**타겟 감사 리스크:**  
특정 계정의 비정상적으로 크거나 작은 금액. 계정별 과거 거래 분포에서 유의미하게 벗어난 금액은 오류 또는 조작의 가능성이 있다.

**탐지 기준:** 계정별 금액의 Z-score가 `z_threshold` 초과

```
z = (amount - μ_acc) / σ_acc
탐지 조건: |z| > z_threshold
```

**파라미터:**  
- `z_threshold: 3.0` — 3σ 초과 (표준 통계적 이상값 기준)
- `min_count: 10` — 계정 내 거래 건수가 10건 미만이면 제외 (소수 거래 계정의 오탐 방지)

**가중치:** 2

**현장 적용 시 주의:**  
Accounts Payable 등 거래 금액 변동이 큰 계정은 정상 거래도 고 Z-score가 나올 수 있다. Threshold를 계정 유형별로 다르게 설정하거나, 계정 범주를 필터링하는 처리가 필요하다.

## Risk Score 산출 구조

```
_risk_score = Σ (Rule_weight × _flag_Rule)

_risk_level:
  score >= 5 → HIGH
  score >= 3 → MEDIUM
  score >= 1 → LOW
  score == 0 → 미탐지
```

**가중치 설계 근거:**

| Rule | 가중치 | 이유 |
|---|---|---|
| Weekend Posting | 1 | 단독 유의성 낮음. 복합 신호로만 의미 있음 |
| Month-end Concentration | 2 | 단독으로도 검토 필요 |
| Reversal Entry | 2 | 추적 필요하나 정상 거래도 많음 |
| Duplicate Journal | 3 | 발견 시 파급력 큼 |
| Unusual Round Amount | 1 | 단독 유의성 낮음 |
| Large Manual Entry | 3 | 내부통제 관점에서 즉시 검토 필요 |
| Debit-Credit Imbalance | 5 | 전표 무결성 오류. 즉시 원인 파악 필요 |
| Account-level Outlier | 2 | 계정 분포 기반 통계적 이상 |
