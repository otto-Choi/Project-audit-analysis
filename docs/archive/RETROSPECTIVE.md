## 프로젝트 배경

정규 스터디 사이클의 개인 프로젝트. 회계감사 업무에서 반복적으로 접하는 SAP GL 데이터 처리를 자동화하고, 이상거래를 config 기반으로 탐지할 수 있는 파이프라인을 구현했다.

출발점은 실무 불편함이었다. SAP GL 데이터는 클라이언트마다 컬럼명도, 금액 형식도, 날짜 형식도 다르다. 매번 수작업으로 맞추는 대신, config 파일 하나만 교체하면 다른 클라이언트 데이터에도 그대로 쓸 수 있는 구조를 목표로 삼았다.

## 잘 된 것들

### config 기반 설계가 의도한 대로 작동했다

처음부터 "코드 수정 없이 클라이언트별 대응이 가능해야 한다"는 원칙을 세웠다. `config_clean.yaml`은 컬럼 매핑과 금액 형식을, `anomaly_config.yaml`은 Rule 파라미터와 가중치를 담는 구조로 분리했다. Rule 추가 시 함수 1개 + config 항목 1개만 작성하면 파이프라인 전체에 반영된다. 이 구조는 Week 6에서 8개 Rule을 한꺼번에 구현할 때 실제로 유효하게 작동했다.

### 파이프라인 전 단계를 6주 안에 완성했다

병합 → 정제 → 탐색 → 이상탐지 → UI까지 6주 만에 모두 구현했다. 노트북(탐색·개발) / src/(생산 함수) / config/(클라이언트 설정) 레이어 분리도 Week 6에 완료됐다. 332,103행 데이터에서 8개 Rule이 정상 작동하는 것을 샘플 데이터로 확인했다.

### Streamlit 드릴다운 탐색 UI가 예상보다 잘 구현됐다

계정 계층 → 원장 → 전표 분개로 이어지는 드릴다운 흐름이 자연스럽게 구현됐다. `on_select="rerun"`과 `session_state` 기반 탐색 히스토리 기능이 핵심이었다. 처음에는 Streamlit의 인터랙티브 기능이 얼마나 될지 불확실했는데, 실제로 구현해보니 회계 탐색 워크플로우에 충분히 맞았다.

### 주차별 설계 문서 작성이 방향 유지에 실제로 도움이 됐다

코딩에 들어가기 전에 설계 문서를 작성하는 방식이 처음에는 속도를 늦추는 것처럼 느껴졌다. 그런데 Week 4~5에서 구현이 복잡해졌을 때, 설계 문서가 "지금 무엇을 만들고 있는가"를 명확하게 잡아주는 역할을 했다. 문서 없이 바로 코드로 들어갔다면 중간에 방향을 잃었을 것 같다.

## 아쉬운 것들

### 단일 데이터셋으로만 검증됐다

모든 정제 설정과 컬럼 매핑이 하나의 SAP 샘플 데이터를 기준으로 맞춰져 있다. "config만 바꾸면 된다"는 설계 원칙이 실제로 얼마나 성립하는지는 다른 클라이언트 데이터를 돌려봐야 알 수 있는데, 그 기회가 없었다. 실무 데이터를 쓸 수 없는 환경에서 진행한 스터디의 근본적인 한계다.

### Rule 품질이 검증 수준에 머물렀다

중복 전표 Rule이 `(doc_no, line_no)` key로 97%를 탐지하는 것은 사실상 오작동이다. 실무에서 중복 전표는 훨씬 까다롭게 정의된다. 차대불균형 Rule도 순금액형 전표 혼재 시 오탐 가능성이 있다. Rule을 만들었지만 튜닝하지 못한 상태로 스터디가 종료됐다. 탐지 수치는 있지만 그게 "좋은 탐지"인지는 보장할 수 없다.

### Benford's Law 미구현

Rule Engine 설계 단계에서 향후 과제로 명시했지만 구현하지 못했다. 전표 금액 첫째 자리 빈도 분포 분석은 이상탐지에서 클래식한 방법이고, 기존 Rule Engine 구조에 함수 1개만 추가하면 됐다. 단순히 시간이 부족해서 남겨뒀다.

## 기술적 의사결정 기록

**왜 Streamlit인가?**  
회계 탐색 도구라면 웹 UI가 필요하다. Flask/Django 대비 데이터 탐색 UI 구현이 훨씬 빠르고, pandas DataFrame을 그대로 다룰 수 있었다. 인터랙티브 기능(`on_select`, `session_state`)이 드릴다운 탐색 구현에 충분했다.

**왜 YAML config인가?**  
클라이언트마다 다른 SAP 포맷 대응이 핵심 목표였기 때문이다. Python 딕셔너리나 JSON도 가능하지만, 주석을 달 수 있고 비개발자도 편집할 수 있는 YAML이 현장 대응 도구에 더 적합했다.

**왜 계정 계층을 Prefix로 자동생성하는가?**  
완전한 계정과목표(Chart of Accounts)가 제공되지 않는 현장이 있다. SAP 계정코드는 앞 1~2자리가 계정 대분류를 나타내는 Prefix 구조를 갖는 경우가 많다. 이를 이용해 계층을 자동 생성하면 계정과목표 없이도 대/중/세분류 구조를 만들 수 있다. 다만 lv1/lv2 한글 계정명은 수동으로 보완해야 하는 한계가 있다.

**노트북과 src/ 분리:**  
Week 4~5는 노트북에서 탐색하며 함수를 개발했다. Week 6에서 디렉터리를 재편하면서 생산 함수는 `src/`로 이전하고 노트북은 개발 워크스페이스로 남겼다. 이 분리 덕분에 `app.py`와 `src/`만 보면 실제 파이프라인 로직이 모두 담겨 있다.
